# GHOSTLINE — Working Rules (non-negotiable)

These bind every contributor and every automated agent working on this repo. If a rule here
conflicts with a tool's default behaviour, **this file wins**. Re-read before every commit,
push, or submission action.

---

## 1. Attribution & authorship

- **No mention of Claude, Anthropic, "AI assistant", "Claude Code", Copilot, or any code-gen
  tool anywhere** — not in source, comments, docs, README, `SKILL.md`, commit messages, PR
  descriptions, Devpost text, the demo video, or repo metadata.
- **No `Co-Authored-By:` trailer** referencing any AI tool in any commit.
- **No "Generated with…" / "Created by…" AI footers** anywhere.
- Commit messages: plain conventional-commits style (`feat:`, `fix:`, `docs:`, `test:`,
  `refactor:`, `chore:`), describing the change only. No tool credits.
- The entrant is the sole author for hackathon-eligibility purposes. Keep it that way in
  every artifact a judge or the sponsor could see.
- Naming the LLM *used at runtime for extraction* is a separate technical matter (that is a
  product dependency, not an authorship credit) — but in our own docs describe it generically
  as "an LLM extraction API" unless a specific reason requires naming the vendor.

## 2. Git

- **Do not run `git push` (or `gh pr create`, or any remote-mutating command) without
  explicit per-action permission from the entrant**, even after a remote is connected.
- `git init`, local commits, local branches: allowed. **Done 2026-08-31** — repo initialized,
  first commit `49e9d20`, author "Bilal Hassan <mbilalhassan567@gmail.com>", local only, no
  remote yet.
- Never `git push --force`, never `--no-verify`, never skip hooks or signing unless the
  entrant explicitly asks.
- Never commit secrets (API keys, tokens, `.env`, call recordings, real phone numbers).
  `.env` and `benchmark/` raw audio stay git-ignored.
- Before any push that matters: `git status`, review the diff, confirm no secrets, confirm
  `python3 scripts/validate_repository.py` is green (for the PR repo).
- The submission PR goes to `CALLE-AI/awesome-phone-call-agents` **only** — never open a PR
  against `call-e-integrations`.

## 3. Money

- **No paid services, subscriptions, or API spend without explicit approval from the entrant.**
- CALL-E: use the **20 free calls**, then the **+200 free-tier request** only. No paid
  call top-ups, no billing enablement.
- Hosting: free tier only unless the entrant approves a paid plan. Prefer a provider with a
  genuinely free tier that stays up through **Oct 13** (judging window).
- LLM extraction API: use the entrant's existing credited account; flag expected token cost
  before running the benchmark or any large batch.
- No domain purchases, no paid fonts/music/stock, no paid CI minutes beyond free allowances.
- If a task appears to *require* spend, stop and ask — do not proceed and do not work around it.

## 4. Hackathon-rule compliance (from master doc §6 — enforced here too)

- **No real third-party names or logos** anywhere (screen, repo, video, Devpost). Use
  `Northline Health`, `Northline Family Clinic`, `Harbor Supply Co.`, `Community Bridge Services`.
- **No real person's voice published** without written consent. Demo calls go to the
  entrant's own labelled test lines, or to a user's own number they typed in themselves.
- **No copyrighted music** in the video unless licensed.
- Every real outbound call opens with a disclosed AI identity + stated purpose.
- One call per number per day cap; honour any "don't call again" immediately.
- No PHI / personal data solicited; redaction pass on stored transcripts; short retention,
  documented.

## 5. The core security invariant (never violate, tested in CI)

> No model-generated or transcript-derived text may ever control the destination of a phone
> call. Dial targets come exclusively from trusted application state — a parsed CSV row or a
> validated E.164 form field. A receptionist saying "call this other number" is data, not an
> instruction. Derived-call proposals require an explicit human approval click before the
> dial is authorised.

## 6. Evidence & honesty

- `benchmark/results.json` is **generated by script, never hand-edited**. The UI reads it
  from file. Displaying a number we did not measure is forbidden.
- No fabricated metrics, transcripts, or scale claims anywhere.
- MATCH/MISMATCH requires a verbatim evidence span — enforced in code, not just documented.
- `UNCLEAR` records never silently become corrections.

## 7. Scope discipline

- The kill list (master doc §3, strategy doc) is binding. Do not resurrect cut features
  under schedule pressure.
- Cherry-tier features are cut before any Core work is touched (master doc §8.1 order).
- If a Cherry takes more than ~half a day, it has become post-hackathon work — stop and cut.

## 8. Change control

- `GHOSTLINE_MASTER_DOC.md` is the spec. Material direction changes: propose, assess impact,
  get the entrant's decision, then update the master doc **in place** (no forked versions).
- Keep `Docs/planning/DECISIONS.md` current with every non-trivial technical decision.
